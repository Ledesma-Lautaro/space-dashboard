<objective>
Fill the shell with real-shaped content: a NEO FEED panel rendering the typed NeoWs fixtures at
realistic numeric density, and a SPACE WEATHER panel rendering DONKI bulletins through the terminal
alert grammar.

Purpose: the phase's stated end state is that the project looks like the finished project with mock
content inside it. That is only true once the panels are populated — and populating them is also what
finally exercises three mechanisms that until now have only been proven in isolation: the character
grid against varied real numbers, the eight-row overflow cap against a collection that genuinely
overflows it, and the alert grammar against a record with no qualifier.

This is also where the phase's one open design question gets its evidence. The terminal face's
horizontal smear is a known legibility risk in dense numeric tables, and the mock fixtures were
specified at realistic density precisely so that question can be answered by eye now instead of after
Phase 4 has been built on top of an unreadable table.

Output: two populated panels mounted in the shell.
</objective>

  <action>
    Render the NEO fixtures as terminal rows inside a `Panel` titled with the feed name and a bare
    numeric count after a double-colon separator. The count is numeric only — no singular or plural
    word form, which designs the grammar problem out rather than handling it case by case.

    Each row shows the object's name, its next close-approach date, its miss distance in lunar
    distances, its relative velocity in kilometres per second, and its estimated diameter as a min-max
    range in metres. Every numeric carries its unit inline. The diameter is rendered as a range and is
    never collapsed to a midpoint or a single figure — the range is the honest value and collapsing it
    would hide real scientific uncertainty that the source data expresses deliberately.

    Surface NASA's hazardous flag verbatim, labelled as NASA's own classification. It is a factual
    field from the source, not a judgement this app makes, and the labelling must say so. Attach no
    alarm to it: no red, no blinking, no warning klaxon copy, no exclamation. The flag is true for a
    large fraction of catalogued objects by design, and dressing it as danger is misinformation. Use
    the alert token family for it if any emphasis is wanted at all — magenta means requires attention,
    and nothing in this phase animates.

    Do not compute or display a notability tier here. That is the asteroid-panel phase's requirement
    and it comes with its own disclaimer obligations; inventing a tier now would ship an unlabelled
    heuristic.

    Lay the row out on the character grid rather than with a fluid table: use a fixed-column grid whose
    column widths are declared in `ch` so numbers align vertically down the panel, which is the whole
    reason for choosing a monospaced face. Right-align the numeric columns so digits line up by place
    value. Body text takes the nominal token; units and the date take the dim token at label size so
    the numbers dominate the row.

    Render more rows than the panel's eight-row cap so the internal scroll is exercised by real content
    rather than only by a synthetic test.

    Do not use the raw-HTML injection API anywhere. All values interpolate as React text.
  </action>

  <action>
    Render the DONKI fixtures inside a `Panel` titled with the space-weather name and a bare numeric
    count of events, as three grouped sections: notification bulletins, then flares, then coronal mass
    ejections and geomagnetic storms.

    Bulletins render through the `Alert` component so the terminal grammar is exercised end to end
    rather than reimplemented. Compose each alert's subject, state, qualifier and value from the typed
    fixture fields — never from a pre-baked display string on the fixture — because the whole point is
    that Phase 5 will compose the same alerts from real records and must find the composition already
    working.

    Include the coronal mass ejection whose analyses array is empty. Its alert must stop cleanly after
    the state with no trailing separator and no filler value, which is the rule this phase established
    and the case that will occur constantly against real data. If any rendered alert in this panel
    shows a dangling hyphen or a stand-in value, the grammar is wrong and must be fixed in the
    formatter rather than patched at this call site.

    Flares show their class type and their peak time. A flare with a null end time renders without an
    end time rather than with a substitute — same principle as the alert degrade rule.

    Storms show their Kp index values. Do not map Kp to the NOAA severity scale here; that mapping is
    the space-weather phase's requirement and belongs with the phase that owns the data. Rendering an
    unlabelled severity now would be a claim this phase cannot stand behind.

    Assign severity by the one colour rule this project uses: green is the base state of everything and
    magenta marks the exceptional. Only the genuinely exceptional records — the highest flare class and
    the strongest storm present in the fixtures — take attention severity. Everything else is nominal.
    Nothing animates.

    Give each group a plain sub-label at label size in the dim token. The sub-labels sit inside the
    panel body and therefore inside the character grid, so keep them at body size if they share a line
    with data and at label size only when they stand alone.
  </action>
