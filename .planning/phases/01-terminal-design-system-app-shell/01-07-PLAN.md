<objective>
Close the phase by making the single-screen layout real at both breakpoints: a canvas region that
reserves exactly the space the WebGL canvas will occupy, an in-theme placeholder inside it, and the
responsive contract that governs canvas height and panel tier at each width.

Purpose: two later phases inherit this layout directly. The render-boundary phase swaps a real canvas
into this region and must not have to redo layout, which is why the placeholder occupies real reserved
dimensions rather than collapsing. The postprocessing phase adds a second CRT source inside that
canvas, which is why the 2D overlay's strength gets its own scale token now rather than being
retrofitted once two CRT layers are compounding. And the mobile-hardening phase's dynamic-viewport
requirement becomes a verification pass rather than a rewrite, but only if every viewport-relative
height in this phase already uses the static small-viewport unit.

Output: a correct single scrolling page at phone and desktop width, with the canvas slot ready to be
filled.
</objective>

    Build the placeholder that fills the reserved canvas region until the render-boundary phase
    replaces it. Its job is threefold: reserve exact layout space so that replacement is a swap rather
    than a layout change, keep screenshots of this phase presentable, and say plainly that the scene is
    not running yet.

    Render the authored offline-scene string from the copywriting contract at display type size,
    centred both horizontally and vertically in the region, in the dim chrome token so it reads as
    structural rather than as data. Beneath it, render the short reserved-render-target readout at

    legible as deliberate rather than as a rendering failure.

    overflow is possible in the largest box on the page, and no truncation rule is needed. Do not add
    one, and do not make either string configurable through a prop — the next phase replaces this whole
    block rather than extending its copy.

    photosensitivity risk source in this project and there is no frame-stepping verification method in

    unplanned.

    phase that will replace it, so a future reader does not mistake the placeholder for finished work.
    Make the region a positioning context so the next phase can absolutely position a canvas element
    inside it without restructuring, and give it the surface background token with the dim border so it
    reads as a bounded region even while empty.

    panels floating over it. The canvas region is a block in the scroll flow above the panels, at both

  <action>
    Declare the responsive contract in one place, with one breakpoint at 768 pixels. Below it, the
    mobile layout; at or above it, the desktop layout. One switch point serves both the canvas-height
    rule and the panel tier scale, and adding a second breakpoint would put the layout rule in two
    places for no gain on a single-screen dashboard.

    Add canvas height tokens to the global stylesheet: a desktop value of one hundred small-viewport
    height units and a mobile value of sixty. Use the small-viewport unit exclusively. Do not
    substitute the dynamic-viewport unit even though general web advice tends to prefer it: the static
    floor is the deliberate choice here, so the hero region and the panels below it never exceed the
    visible area before the first scroll and nothing resizes as browser chrome collapses. That choice
    is what turns the final phase's mobile chrome requirement into a verification pass. Audit every
    stylesheet in the project for a bare viewport-height unit and replace any occurrence.

    Apply the desktop canvas height above the breakpoint and the mobile height below it. The vertical
    order is identical at both: canvas region, panels region, legend strip. Only the canvas height and
    the panel tier change across the breakpoint — never the order, and never the composition.

    Snap panels to the compact tier below the breakpoint and the default tier at or above it. Drive
    this from a modifier on the panels region rather than by branching in JavaScript on a measured
    width, so the server render and the first client render agree and no hydration surface is created.
    Because the panel already degrades below the compact tier through its container query, the two
    mechanisms compose: the media query selects a tier, the container query decides whether that tier's
    ASCII chrome can be drawn at all.

    Centre the content column horizontally with a maximum width equal to the wide tier so the layout
    does not stretch across an ultrawide display, and give it horizontal gutters from the large spacing
    token plus safe-area insets so content clears a notch or a rounded corner on a phone.

    Add a dedicated scale token for the 2D CRT overlay's strength, applied as a multiplier alongside the
    existing intensity in the scanline and vignette opacity calculations. The overlay's absolute
    strength must be adjustable without touching the user-facing intensity level, because the
    postprocessing phase introduces a second CRT source inside the canvas and the two will need
    balancing against each other. Default the scale to one so nothing changes visually today; the point
    is that the seam exists before there are two sources compounding.

    Finally, confirm the App Router still contains exactly one route and no route segments — this is the
    single-screen requirement, and the design system is delivered as the in-page legend strip precisely
    so no style-guide route is ever needed.
  </action>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-18 | Denial of Service | Canvas region height under collapsing browser chrome | medium | mitigate | Size the region with the static small-viewport unit rather than the dynamic one, so collapsing or expanding browser chrome never resizes the region or clips content below it. An automated gate rejects any bare viewport-height unit in any stylesheet. This is the control that keeps the final phase's mobile requirement a verification rather than a rewrite. |
| T-01-19 | Denial of Service | Layout overflow at very narrow viewports | low | mitigate | The content column is capped at the wide tier and gutters include safe-area insets; the panel's own container-query degrade covers widths below the compact tier. Together these bound horizontal overflow at every supported width. |
| T-01-20 | Tampering | Compounding CRT sources once the canvas renders | low | mitigate | Introduce the independent 2D overlay scale token now, defaulting to no visual change, so the postprocessing phase can dial the CSS layer down against the shader chain instead of discovering the two layers compound into unreadable text. Structural mitigation of a known downstream legibility failure. |

authored constants, reading no runtime input.
