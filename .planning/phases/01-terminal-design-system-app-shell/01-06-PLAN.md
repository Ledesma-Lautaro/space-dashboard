<objective>
Build the palette legend that explains the project's colour vocabulary, render it inside the shared
terminal chrome, and give the CRT intensity control its permanent home beside it.

Purpose: the colour rule this project uses is deliberately minimal — one hue for the routine, one for
the exceptional, three brightness steps for emphasis — and it is only defensible if it is stated
somewhere a visitor can read. That statement is a tracked requirement, and it is also what keeps the
scheme accessible: a visitor who cannot reliably separate green from magenta can still read every
state from the brightness step, but only if the legend tells them the steps mean emphasis rather than
a different category.

Delivering it as an in-page strip rather than a separate style-guide route is a locked decision, and
it is the same decision that keeps the dashboard a single screen with scroll and no separate routes.

Output: a legend strip containing the colour semantics and the CRT control, mounted in the shell.
</objective>

  <files>src/components/ui/Legend.tsx, src/components/ui/Legend.module.css</files>
  <action>
    Build the legend inside the shared `Panel` chrome titled with the system-legend name, at the
    default tier. Do not invent separate markup for it — reusing the panel is what keeps the design
    system one vocabulary rather than two.

    Author exactly two colour entries plus one qualifying note, in the terminal register the
    copywriting contract fixes: a hash swatch, the colour name, a double-colon separator, and the
    meaning. Green means nominal and routine; magenta means requires attention. Then a single indented
    note stating that brightness is emphasis, not a different meaning.

    Colour each swatch with the token family it names — the green entry's swatch in the nominal token,
    the magenta entry's swatch in the alert token — so the legend demonstrates the colour it describes
    rather than merely naming it. Never use the dim step of the alert family for any text or swatch: at
    2.46 to 1 against the background it fails contrast even for large text, and it exists for
    decorative borders only.

    Use the hash character as the swatch. Do not use a Unicode block or geometric-shape glyph — the
    terminal face contains none of them, so any such character would render from a fallback font at a
    different advance width and break the character grid the panel depends on.

    Demonstrate the brightness vocabulary concretely rather than only describing it: render the three
    steps of the nominal family as a short sample row so the qualifying note has something to point at.
    Keep it to one line.

    Render the CRT intensity control inside this component, below the colour entries, separated by the
    medium spacing token. A visitor learning what the colours mean is exactly the visitor who wants to
    know they can turn the effect down, and this is the strip the design system is delivered as.

    Entries are hand-authored in source and never fetched. Add a short comment recording that adding an
    entry means re-checking the longest line against the tier's character cap at authoring time — with
    the corrected character advance the longest current line has comfortable margin, but that margin is
    finite and the check is cheap.

    Give the legend a heading structure that reads correctly to a screen reader: the panel title is the
    heading, the entries are a list, and the sample row is not announced as content since it is purely
    demonstrative.
  </action>
