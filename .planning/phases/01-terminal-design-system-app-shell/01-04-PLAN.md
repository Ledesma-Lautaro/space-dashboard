<objective>
Author the typed, realistically-dense mock payloads this phase renders and the `Alert` component that
turns a record into a terminal bulletin.

Purpose: two things depend on getting the data shapes right now rather than later. First, VT323's
horizontal phosphor smear is a known legibility risk in dense numeric tables, and that risk is only
observable against real numbers with real units — which is why the mock data is specified as
realistic-density rather than as lorem or skeletons. Second, Phase 3 reuses these exact fixtures to
exercise its loading, rate-limited, unavailable and empty states, so the types authored here are the
types the fetch layer will consume, not throwaway approximations.

The alert grammar is fixed by requirement, including the case that matters most: a record whose
qualifier is missing. Real DONKI CMEs routinely arrive with no analysis entry and therefore no
intensity; the grammar drops the clause rather than inventing a value.

Output: two type modules, two fixture modules and a terminal `Alert` component with a pure formatter.
</objective>

  <files>src/components/ui/Alert.tsx, src/components/ui/Alert.module.css</files>
  <action>
    Build the alert as its own component with its own prefix, severity colour and spacing — not as a
    panel modifier (D-15), so Phase 5 can drop real bulletins into it without touching panel chrome.

    Export a pure `formatAlertLine` that composes the fixed grammar: a double-angle prefix, a space,
    the subject, a space, the state, then — only when a qualifier and a value are both present — a
    space, a hyphen, a space, the qualifier, a colon, a space and the value. The requirement's own
    example, a detected coronal mass ejection with a moderate intensity, is the canonical shape.

    The degrade rule is the part that matters and it is a new decision this phase makes rather than
    inherits: when the qualifier or the value is absent, drop the entire trailing clause. Do not emit a
    filler token in the value slot and do not emit a dangling hyphen. A record with no analysis entry
    produces a subject and a state and stops there. Phase 5 inherits this rule for real records.

    Keep alert content to a single line of meaning — no secondary explanatory body copy under a
    terminal statement, because the one line is the message. Uppercase-leaning register, units inline
    on any numeric value, no trailing punctuation beyond what the format itself contains.

    Render through React's default text interpolation. Never use the raw-HTML injection API, even
    though DONKI message bodies in Phase 5 will be untrusted remote text — establishing that habit here
    is why this component exists now rather than in Phase 5.

    The component takes a severity of nominal or attention, defaulting to nominal. Attention takes the
    alert token family; nominal takes the nominal family. Green is the base state of everything and
    magenta marks the exceptional (D-13), so a bulletin is only ever magenta when it genuinely requires
    attention. Give the alert a left accent border in its severity colour, its own vertical spacing
    from the small spacing token, and the phosphor glow at the normal radius in its own hue.

    Alerts carry no character-grid chrome, so text wraps freely: preserve authored whitespace and allow
    long tokens to break, and never truncate. This is the deliberate difference from a bordered panel.

    When the component receives no content it renders nothing at all — return null rather than an empty
    styled shell, so an alert feed with nothing in it leaves its containing panel to show the panel's
    own empty presentation rather than stacking two empty states.

    Alert copy for the loading, error and empty states is not authored in this task. Those states have
    no source of truth until a fetch layer exists, and their grammar is already fixed in the
    copywriting contract for the data phase to implement verbatim. Do not invent variants of them here.
  </action>
